> **Changed:** Implemented the initial Alembic migration for the `ai` schema and vector extension, leaving the V1 business tables for later feature work.

## Engine

PostgreSQL 16 with the **pgvector** extension, accessed through **SQLAlchemy 2.x (async)** with the
**asyncpg** driver. Migrations are managed with **Alembic**.

- The data access layer is **async**: every repository function is `async` and must be awaited.
- AI data lives in the **`ai` schema** (owned by the AI team).
- Backend data lives in the **`core` schema** (owned by the backend team). The AI service only **reads**
  it, using a read-only database user, if direct access is agreed (open question).
- **Row-level security (RLS)** is enabled on every `ai` table. Each session sets the current workspace,
  and queries only see that workspace's rows.
- Nothing is updated in place: AI outputs are **versioned** (new row per change).

---

## Connection

`app/data/db.py` creates one async engine and one session factory at startup.

- `get_engine()` — returns the shared async engine (connection pool; created once, reused).
- `workspace_session(workspace_id)` — async context manager that opens a session, runs
  `SET LOCAL app.workspace_id = :workspace_id` inside a transaction, and closes it afterwards.
  **Every** read and write uses this session, so row-level security always applies.
- `dispose_engine()` — closes the pool on shutdown and in test teardown.
- Celery workers create their own engine per worker process (pools are not shared across processes).
- Tests use a separate test database; each test runs in a transaction that is rolled back.

## Schema

> Keep these in sync with the Alembic migrations. **V1** = needed now. Others = planned.
> All IDs are text with a short prefix, generated by the application (for example `job_9a3c5d81`).
> All tables include `workspace_id` and `project_id` and are protected by RLS.

### jobs (V1)

One row per agent request from the backend.

```sql
CREATE TABLE ai.jobs (
  id            TEXT        PRIMARY KEY,
  workspace_id  TEXT        NOT NULL,
  project_id    TEXT        NOT NULL,
  agent         TEXT        NOT NULL,
  input_ref     TEXT,
  status        TEXT        NOT NULL DEFAULT 'queued',
  error_reason  TEXT,
  requested_by  TEXT,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  started_at    TIMESTAMPTZ,
  finished_at   TIMESTAMPTZ
);
```

| Column | Type | Notes |
|--------|------|-------|
| `id` | TEXT | PK, `job_` prefix |
| `agent` | TEXT | Agent name, e.g. `intake_summary` |
| `input_ref` | TEXT | ID of the input (e.g. intake ID) |
| `status` | TEXT | `queued` / `running` / `done` / `failed` |
| `error_reason` | TEXT | Set when `failed` |
| `requested_by` | TEXT | User ID passed by the backend |

### runs (V1)

One row per model call inside a job (for tracing and cost).

```sql
CREATE TABLE ai.runs (
  id              TEXT        PRIMARY KEY,
  job_id          TEXT        NOT NULL REFERENCES ai.jobs(id),
  workspace_id    TEXT        NOT NULL,
  project_id      TEXT        NOT NULL,
  step            TEXT        NOT NULL,
  model           TEXT        NOT NULL,
  prompt_version  TEXT        NOT NULL,
  tokens_in       INTEGER,
  tokens_out      INTEGER,
  duration_ms     INTEGER,
  retries         INTEGER     NOT NULL DEFAULT 0,
  status          TEXT        NOT NULL,
  trace_id        TEXT,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

| Column | Type | Notes |
|--------|------|-------|
| `step` | TEXT | Agent step, e.g. `summarise` |
| `model` | TEXT | e.g. `qwen3.5:4b` |
| `prompt_version` | TEXT | e.g. `intake_summary@v1` |
| `trace_id` | TEXT | Langfuse trace ID |

### intake_summaries (V1)

AI-generated summary of one intake (draft until the user verifies it).

```sql
CREATE TABLE ai.intake_summaries (
  id                TEXT        PRIMARY KEY,
  job_id            TEXT        NOT NULL REFERENCES ai.jobs(id),
  workspace_id      TEXT        NOT NULL,
  project_id        TEXT        NOT NULL,
  intake_id         TEXT        NOT NULL,
  version           INTEGER     NOT NULL DEFAULT 1,
  status            TEXT        NOT NULL DEFAULT 'ai_draft',
  summary           TEXT        NOT NULL,
  problem_category  TEXT        NOT NULL,
  key_points        JSONB       NOT NULL,
  gaps              JSONB       NOT NULL,
  created_by        TEXT        NOT NULL DEFAULT 'ai',
  created_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (intake_id, version)
);
```

| Column | Type | Notes |
|--------|------|-------|
| `version` | INTEGER | 1 = AI draft; higher = verified/edited versions |
| `status` | TEXT | `ai_draft` / `verified` |
| `key_points` | JSONB | `[{ point, from_question }]` |
| `gaps` | JSONB | `[text]` |
| `created_by` | TEXT | `ai` or the user ID who verified/edited |

### Row-level security (every table)

```sql

  USING (workspace_id = current_setting('app.workspace_id'));
```

## Queries

> All SQL lives in `app/data/queries/` as named SQLAlchemy statements — never in API routes, agents or tasks.

| Constant | Operation |
|----------|-----------|
| `INSERT_JOB` | Insert a new job (`queued`) |
| `UPDATE_JOB_STATUS` | Set job status, timestamps and error reason |
| `SELECT_JOB_BY_ID` | Get one job |
| `INSERT_RUN` | Insert one model-call record |
| `INSERT_INTAKE_SUMMARY` | Insert a summary version |
| `SELECT_LATEST_SUMMARY_BY_INTAKE` | Get the latest summary version for an intake |
| `SELECT_SUMMARY_VERSIONS_BY_INTAKE` | Get all versions for an intake |
| `INSERT_LEARNING_EVENT` | Record a verify/edit event |

> Queries for planned tables are added when their phase starts.

## Repository Functions

> Agents, tasks and API routes call these — they never touch the database directly.
> Every function takes an open `workspace_session`.

| Function | Parameters | Returns | Description |
|----------|------------|---------|-------------|
| `create_job(s, data)` | `JobCreate` | `Job` | Insert a job with status `queued` |
| `set_job_status(s, job_id, status, error=None)` | `str, JobStatus, str \| None` | `None` | Update status and timestamps |
| `get_job(s, job_id)` | `str` | `Job \| None` | Find a job by ID |
| `record_run(s, data)` | `RunCreate` | `Run` | Save one model-call record |
| `save_summary_draft(s, data)` | `IntakeSummaryCreate` | `IntakeSummary` | Insert version 1 (`ai_draft`) |
| `save_verified_summary(s, intake_id, data, user_id)` | `str, IntakeSummaryUpdate, str` | `IntakeSummary` | Insert next version (`verified`) |
| `get_latest_summary(s, intake_id)` | `str` | `IntakeSummary \| None` | Latest version for an intake |
| `record_learning_event(s, data)` | `LearningEventCreate` | `None` | Save a verify/edit event |

## Adding a New Query

1. Add the SQLAlchemy statement as a named constant in `app/data/queries/<table>.py`.
2. Add an `async` repository function in `app/data/repositories/<table>.py` that takes a
   `workspace_session` and returns a Pydantic model (never raw rows).
3. Call the repository function from the agent tool, task or API route.
4. Never write SQL directly in an agent, task or route.
5. Schema changes only through a new Alembic migration; never edit an applied migration.
6. New tables must include `workspace_id` and `project_id`, enable RLS, and add the
   `workspace_isolation` policy in the same migration.
7. Update this file in the same change.
